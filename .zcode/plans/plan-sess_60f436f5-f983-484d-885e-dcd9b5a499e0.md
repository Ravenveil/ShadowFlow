# Neo 跳转逻辑收敛 — 单一导航状态机

## 问题与根因

三连报（知识库/记忆不跳、右栏不出现、现在团队不跳）同一根因：**跳转意图分散在三处状态里，每条入口各自手工拼线**——

- NeoRail 本地：`section`（home/agents/teams/knowledge/memory）+ `view`（personal/team）
- NeoApp 状态：`target`（编排目标）+ `midView`（conversation/knowledge/memory）+ `runId`
- 各点击入口自行组合 `setSection / changeView / onSelect / onOpenPage / onOpenConversation / onNewTask`，漏调任何一根线就是"点了没反应"或"状态打架"

本次把**中栏视图 + 左栏列表区收归 NeoApp 一处持有**，NeoRail 变成纯受控组件；所有点击走唯一入口 `onNavigate`。此后加导航入口 = 加一个变体 + 一行渲染映射，列表/中栏/高亮不可能再分叉。

## 导航模型（src/neo/types.ts）

```ts
/** 唯一导航状态：中栏视图 + 左栏列表区都由它派生。 */
export type NeoNav =
  | { view: 'home' }                                  // 新任务 hero（列表=会话）
  | { view: 'knowledge' }                             // 知识库页（列表=分包）
  | { view: 'memory' }                                // 记忆页（列表=条目）
  | { view: 'agents' }                                // 浏览员工（列表=员工）
  | { view: 'teams' }                                 // 浏览团队（列表=团队+群聊现场）
  | { view: 'conversation'; groupId: string }         // DM/群聊内嵌（列表不动）
  | { view: 'agent-target'; agentId: string; name: string }  // 后端不可用兜底
  | { view: 'team-target'; teamId: string; name: string };   // 后端不可用兜底
```

## 核心改动

### 1. NeoApp（唯一持有者）
- `target` + `midView` 两态合并为 `nav`；`target` 变派生值（agent-target/team-target → NeoTarget，其余 null），NeoHost 编队 tab 逻辑不动。
- `onNavigate(next)`：setNav + 纯函数映射默认列表区（home→会话 / knowledge→分包 / memory→条目 / agents→员工 / teams→团队；conversation 不改列表）。
- 中栏渲染纯查表：conversation→`NeoGroupChat embedded`；knowledge/memory→内嵌页；**agents/teams/home/兜底→NeoChat**（点导航行中栏落到新任务 composer——每个导航行都有明确落点，不再"点了没跳"）。
- 右栏规则不变：run ∨ conversation ∨ target；knowledge/memory 不套 440px 窄列。
- `handleNewTask` = `onNavigate({view:'home'})` + 清 runId。

### 2. 团队行点击 → 打开该团队群聊现场（新行为，修本次报障）
后端群聊网关本就按 `group.team_id` 触发团队 DAG（`server/src/routes/groups-chat.ts:109`）——**团队的干活现场就是它的群**，与员工点击开 DM 同构：

- `src/api/groupApi.ts` 新增 `resolveTeamGroup(team, workspaceId)`：`listGroups(workspaceId)` 客户端过滤 `team_id` 命中即返回；未命中 `createGroup({ teamId, agentIds: team.agent_ids, name: team.name, templateId:'new-task', … })` 建群并返回（**find-or-create，与 DM resolve 同款模式，首次点击会建一条群数据**）；失败返回 null。
- NeoRail 团队行（展开态 752 / 折叠态 475 两处）改走 `openTeamChat`：resolve 成功 → `onNavigate({view:'conversation', groupId})` + 刷新 inbox（群聊现场列表即时出新群）；失败 → 兜底 `team-target`（现状行为，右栏编队 tab）。
- 佐证：Explore 已核实无 team→group 后端端点，客户端 join 是唯一通路；`listGroups` 现成零调用方、`POST /api/groups` 两端都持久化 `team_id`。

### 3. NeoRail（变纯受控）
- props 换成 `{ nav, onNavigate, onNewTask, collapsed, onToggleCollapsed }`；删除 `onSelect/onOpenConversation/onOpenPage`。
- 删本地 `section`/`view` 两态（列表区与选中高亮全部从 `nav` 派生；`VIEW_KEY` 持久化随之删除）；`searchOpen` 保留（纯 UI）。
- 全部点击重写为 `onNavigate(...)` 一个动词；会话/群聊行高亮改比 `nav.groupId`（原来比 target，开群聊后高亮会丢）。

### 4. NeoChat（小改）
- `onOpenConversation(groupId)` 顶栏入口换成 `onNavigate({view:'conversation', groupId})`。

### 5. 测试与验证
- `NeoRail.test.tsx`：props 适配折叠回路用例；新增"团队行点击 → mock resolveTeamGroup → onNavigate 收到 conversation+groupId"。
- 回归：tsc / eslint / vitest（neo + 路由）。
- 无头浏览器实测清单：团队导航行→团队列表+中栏跳新任务；**团队行→中栏开该团队群聊（无群自动建）**；员工行→DM；知识库/记忆行→内嵌页；新任务→hero；右栏出现规则不回归。

## 边界与说明
- 首次点团队会自动建群（find-or-create）——与点员工自动开 DM 同款既定模式，风险仅在点击产生一条群记录。
- 会话视图刷新不恢复是既有行为，不在本次范围。
- 并行会话仍在改同批文件：动手前重读、改完即回归验证。
