# 修订计划：单聊编排 → 分阶段派发 → 群聊现场（Polynoia 对标）

目标形态（用户设想，与 Polynoia 5+1 状态机同构）：

```
Neo 单聊页说话 ──→ 编排者理解意图 ──→ plan_card 拆解可视化（单聊内）
      │                                    │
      │（B1 互链：单聊 run ↔ 群，已存在）      ▼
      │                        INTENT_PARSE：LLM 生成 per-agent 子任务 prompt
      ▼                                    ▼
  跳转群聊页 ◄──────────── DISPATCH：DAG 分层并行派发（同层并行）
  （看 agents 干活现场）                    ▼
                           AGGREGATE → EMIT_PREVIEW（web_preview 卡）
                                           ▼
                           MERGE：worktree 提交/合并/冲突浮出（commit/file_diff/table 卡）
```

## 交付物 1：WorktreeManager（`server/src/lib/worktree-manager.ts` 新建）

Polynoia「每 agent 一分支一 worktree → 干完 merge --no-ff → 冲突标 needs-manual」的落地，风格对齐 git-introspect.ts（防御式，非 git 仓库 → null 绝不 throw）：

- `prepareWorktree(repoRoot, runKey, agentId)`：worktree 在 `<repoRoot>/.shadowflow/worktrees/<runKey>/<agentId>`，分支 `agent/<agentId>/<runKey>`（对齐 Polynoia 命名）；已存在时回合重置（reset --hard 基准 + clean -fd）
- `commitWorktree(dir, message, author)`：有变更才提交，agent 身份作 author，返回 commit_record 数据
- `integrateAll(repoRoot, runKey, branches[])`：专用集成分支上逐分支 `merge --no-ff`；冲突收集 `--diff-filter=U` 清单后 abort，标 needs-manual；不碰用户检出分支

## 交付物 2：群 DAG 路径补 INTENT_PARSE + DISPATCH + MERGE（groups-chat.ts）

1. **编排者前置拆解（INTENT_PARSE）**：`runFanout` 团队分支入口新增可选 LLM 拆解——复用 BYOK 通道（`/api/llm/messages` 同源的内部调用），把用户消息拆成 `{agentId → 子任务 prompt}`（JSON，含阶段/依赖说明）；无 key/解析失败 → 降级为现状（原文分发），零回归。拆解结果驱动 plan_card 任务标题（不再是裸 agent 名）
2. **plan_card 编排卡（DISPATCH 可视化）**：`computeDagLayers` 分层 → plan_card（层号=并行批次）经 projector + gw 下发；callAgent 外包一层发 `plan_update_task` 实时状态（闭包已收到 agentId）
3. **worktree 注入**：`resolveCallable` 的 workspace 换成该 agent 专属 worktree + git 身份 env；群 workspace 非 git 仓库 → 行为与现状一致。单 agent 串行回退路径同样替换（不发卡）
4. **回合收尾（AGGREGATE/MERGE）**：worker 成功 → `commitWorktree` → commit_record + file_diff 卡；DAG 结束 → `integrateAll` → 合并结果卡、多文件 table_panel、冲突表格卡 + 系统消息（needs-manual）
