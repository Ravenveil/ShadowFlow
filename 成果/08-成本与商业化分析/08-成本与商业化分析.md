# 08 · 运营成本与商业化分析

> 对应《AI 赛道项目提交材料说明》第 8 项：**40+ 小时内 Token 消耗、模型调用费用、其他运营成本、
> 与传统人工同等工作量的成本对比——量化 Agent 组织的效率与成本优势。**
>
> 数据源：GitHub 新线 ShadowFlow-main（Node/TS）实跑数据（与材料 6 同一数据底座：54 单经营流水 +
> 10 个 Agent 会话）；Token 为**实测**（方法见附录）；模型定价取**小米 MiMo 开放平台官方按量计费页**
> （2026-11-07 查询）；人工薪资参照**公开招聘数据**（来源见正文标注）。
> 凡属假设的参数，全部显式列出，不编小数。

## 摘要（结论先行）

| 结论 | 数字 | 口径 |
|---|---|---|
| 模型调用费极低 | 10 会话窗口累计 **¥0.19**（mimo-v2.6-pro）/ ¥0.06（flash） | 实测载荷 × 官方定价 |
| 每个完整营销会话成本 | **≈ 2 分钱**（Pro） | 1 次调用/会话，实测载荷 |
| 每单综合成本（代运营口径） | **≈ ¥11–12** | AI≈0 + 人工监督折算 + 工具摊销 |
| 与传统 9 岗位团队对比 | 同等工作量 **≈ 20× 成本差**（每单 ¥2.2 vs ¥46） | 公开薪资区间假设，见第六节 |
| 单位经济（内容包口径） | ¥99/单，毛利 **≈ ¥79（80%）** | 演示口径，获客成本未计入 |
| 40+ 小时窗口模型费上限 | 保守分轮口径也 **< ¥3** | 敏感性测算，见第三节 |

**一句话**：一人公司 + Agent 组织的单位经济里，Token 是最便宜的一项——真正的稀缺资源是老板的
监督时间；模型成本低到可以忽略，意味着**边际交付成本主要由人工监督分钟数决定**，而后者随流程
自动化持续下降。

## 一、40+ 小时窗口运营成本总览

| 成本项 | 窗口实测/测算 | 占比 | 口径 |
|---|---|---|---|
| 模型调用费 | **¥0.19**（Pro）/ ¥0.06（Flash） | <0.1% | 见第二、三节，实测 |
| 服务器托管 | ¥0（自有开发机跑隔离实例） | 0% | 演练期不租云；生产估算 ¥100–200/月 |
| 工具与订阅 | ¥0–50/月摊 | ~1% | 开发工具免费额度内 |
| 人工监督（老板） | 约 2–3 人时/日复核 × 2 天 ≈ ¥400–500（机会成本折算） | **~98%** | 时薪假设 ¥80/h，见第六节 |
| **合计（窗口）** | **≈ ¥400–500**，其中现金支出 ≈ ¥0.2 | | 人力以机会成本计 |

> 结构性结论：**运营成本≈人工监督成本**。模型费用哪怕按最保守口径放大 100 倍（¥19）也只占 ~4%。
> 这是"一人公司"成立的成本基础——AI 员工的边际成本趋近于零，组织规模只受监督带宽约束。

## 二、Token 消耗实测

### 方法（三层交叉验证，全部可复现）

| 层 | 测什么 | 怎么测 | 数据文件 |
|---|---|---|---|
| A · 管线记录计数 | 每会话装配/思考的 Token 计数器 | 解析 10 会话 × 167 事件的事件流 JSON，逐事件累加 | `token实测-按会话.csv` |
| B · API 调用计量 | 真实发给模型 API 的载荷 | 给 OpenAI 兼容桩加计量中间层，逐调用记录消息字符数（2 会话抽样） | `token实测-API调用计量.csv` |
| C · 产物落盘 | 实际产出物体量 | 项目目录文件逐个字节统计 | 材料 6 `04-产物-*/`（1,956 字节/会话） |

> ⚠️ 诚实标注：执行模型为**本地确定性桩**（流程、交接、留痕、落库全真实，产出内容可复现）。
> 层 B 计量的是**真实发往模型端点的请求载荷**——这正是接入 MiMo API 时的计费输入面；
> Token 估算系数取 **1.5 字符/Token**（中文为主的经验值），并给出 1.2–2.0 系数的敏感性。

### 实测结果

**层 A（10 会话事件流）**：
- 1,670 个事件（每会话 167 条，含完整三相位：蓝图 → 双员工 5 substep 装配 → 双产物 → complete）
- 记录 Token 合计 **11,410**（其中 substep 装配 10,800 全部缓存命中、thinking 610）
- 消息文本载荷 3,430 字符

**层 B（API 调用计量，2 会话抽样）**——每会话 **1 次** chat completion（agent-first 单流三相位设计）：

| 指标 | 实测值 | 折算 Token（1.5 字符/T） |
|---|---|---|
| 调用次数 | 1 次/会话（流式） | — |
| 输入载荷 | 315–395 字符（系统提示 287–327） | ≈ 210–265 |
| 输出载荷 | 4,545 字符（蓝图+双员工+双产物全文） | ≈ 3,030 |
| **每会话合计** | — | **≈ 3,240–3,295** |

**窗口折算（10 会话）**：输入 ≈ 2.1–2.7K + 输出 ≈ 30.3K = **≈ 32.4–33.0K Token**。
估算系数敏感性：1.2 字符/T → 约 41K；2.0 字符/T → 约 24K。量级不变。

## 六、与传统人工同等工作量的成本对比

**同等工作量定义**（与实跑对齐）：1 场营销交付 = 1 次产品调研（调研笔记）+ 1 篇成品文案（3 条种草帖）+
发货要点，支撑约 10 单成交。

### 传统团队：9 岗位协作

薪资参照：谈职公开招聘数据（2026-10 更新）——文案策划中位 ¥6,500–9,500/月（长沙/杭州口径，
深圳均值 ¥10,100）、内容策划中位 ¥10,000/月；其余岗位按同城市同资历区间取中位假设，雇主综合
成本系数 1.35（社保公积金）。

| 岗位 | 月薪中位假设 | 在每场交付中投入 |
|---|---|---|
| 市场调研 | ¥8,000 | 2 小时 |
| 营销策划 | ¥9,000 | 1 小时 |
| 文案 | ¥8,000 | 2 小时 |
| 设计 | ¥8,500 | 1 小时 |
| 财务 | ¥7,000 | 分摊 0.5 小时 |
| 项目管理 | ¥9,000 | 分摊 0.5 小时 |
| 质检 | ¥7,000 | 分摊 0.5 小时 |
| 合规 | ¥8,000 | 分摊 0.5 小时 |
| 客服 | ¥6,000 | 1 小时 |

- **每场交付人力成本**：≈ 8 人时 × 各岗综合时薪（月薪中位 ÷ 21.75 天 ÷ 8h × 1.35，
  约 ¥46–73/h）≈ **¥370–580**，取中 **≈ ¥460/场 → ¥46/单**（10 单摊）。
- **月度框架**：9 岗位全职团队雇主综合成本 **≈ ¥8–11 万/月**。

### Agent 组织：一人公司

| 岗位职能 | 由谁完成 | 每场成本 |
|---|---|---|
| 调研 / 文案 / 策划 / 质检初稿 | Agent（调研员 + 撰稿人，167 事件留痕） | AI ¥0.02 |
| 财务对账 / 合规初筛 | Agent（三叠钱自动对账、口径校验） | 含在 ¥0.02 |
| 项目管理 / 客服 / 最终决策 | **老板不可替代**（15 分钟复核/场 + 6 分钟/单） | ¥20/场 + ¥8/单 |
| **每场交付成本** | | **≈ ¥20.02 → ¥2.2/单** |
| **月度框架** | 1 人 ¥8,000 + 模型 <¥5 + 工具 ≈¥200 | **≈ ¥8.2 千/月** |

### 对比结论

| 维度 | 传统 9 岗位 | 一人公司 + Agent | 差距 |
|---|---|---|---|
| 每场交付成本 | ≈ ¥460 | ≈ ¥20 | **≈ 23×** |
| 每单摊销成本 | ≈ ¥46 | ≈ ¥2.2 | **≈ 21×** |
| 月度组织成本（同产出） | ¥8–11 万 | ¥8.2 千 | **≈ 10–13×** |
| 边际第 100 单 | 同单价 | 模型费 +¥0.2 | 边际成本趋零 |
| 交付时效 | 串行排期 2–5 天 | 会话级分钟–小时 | — |
| 留痕/可审计 | 靠人整理 | 167 事件/会话逐条可回放 | — |

> 量级结论稳健：即使把 Agent 侧的人工监督时间放大 3 倍（45 分钟/场），或把模型口径用最保守
> 分轮上限（¥0.216/场），每场仍为 ¥36 vs ¥460 ≈ **12×**。核心驱动是**人机分工**——
> 老板只做不可替代决策（选题、终审、客情），其余全部交给可留痕、可回放、近零边际成本的 Agent。

## 七、商业化路径

1. **定价分层**：残障匠人公益价（低佣/免佣，承担社会责任叙事）+ 商业客户市场价（15–20% 佣金）；
   营销内容包 ¥99/单作引流品。
2. **获客**：手工艺人社群/残联合作渠道（B 端，获客成本待实测）；首批客户以案例换推荐。
3. **复购模型**（演示可演）：买过内容包推代运营、买过代运营推选品体检，客单递增；
   客户意见自动带入记忆交接，降低返工成本。
4. **规模化曲线**：单店月 130 单（实跑节奏外推）→ 一人可并行监督 3–5 店；此后瓶颈是
   老板监督带宽而非算力，扩产能靠流程模板化 + 员工 Agent 复用（记忆交接/画像写回已具备）。
5. **盈亏平衡**（代运营口径）：固定成本 ≈ ¥8.2 千/月 ÷ 每单毛利 ¥7–14 ≈ **590–1,170 单/月**——
   即 4–9 家店铺的经营规模；内容包口径则 **105 单/月**即平。

## 八、风险披露（诚实标注）

- 本窗口为**演练数据**：下单/支付走模拟沙箱（不产生真实扣款），执行模型为本地确定性桩；
  流程、留痕、落库、对账全部真实，产出可复现。
- Token 估算系数（1.5 字符/Token）与"每会话 1 次调用"是**本流水线实测形态**；真实业务的
  长 Brief / 多轮修订会推高消耗，已用保守上限口径（第三节）覆盖。
- 佣金率 15–20%、时薪 ¥80、6–15 分钟监督时长、复购率均为**显式假设**，随真实运营校准。
- **获客成本未计入**单位经济；真实支付/经营资质未办理；薪资数据为第三方招聘平台公开区间
  （谈职，2026-10 更新），仅供量级参照。
- 与人工对比按"同等工作量"定义换算，岗位投入工时为假设值，不构成对任何真实团队的报价。
