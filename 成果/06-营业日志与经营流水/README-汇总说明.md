## 这批数据是怎么跑出来的

**① Agent 运行（营业日志）**——Day-1 主流程累计跑了 **22 个完整会话**（11 轮 × 每轮 1 主会话 + 1 custom 通道冒烟会话）：
创建项目 → 提交 Brief → GM 生成计划卡（调研员/撰稿人 2 任务行）→ 双员工逐棒装配
（每人 identity→persona→model→tools→memory 共 5 个 substep 状态翻转）→ 双产物落盘 → complete →
critique 质检（评审请求被上游 403 拒绝，错误原文逐字节留痕）。主会话走 `byok:anthropic`
（Anthropic 协议通道）、冒烟会话走 `byok:custom-day1`（OpenAI 兼容协议通道）——
**双协议通道**均经本地确定性模型桩回放（流程、交接、留痕、落库全部真实，产出内容可复现）。
每会话 **168 条事件**全程留痕（167 条核心事件 + 1 条 team-saved 团队落库事件）；
**22/22 会话事件流形态校验通过**（事件数 167–169、无 usage 噪声、critique 403 复现、complete 落盘）。

**② 经营（经营流水）**——商家域真实落库，六个批次连续经营：
- 批次 1（首日）：上架 6 件手工艺品 → 10 次访问 → 12 单（含 1 单留未付验证口径）；
- 批次 2（晚市 + 次日两波）：再上架 8 件 → 再 12 次访问 → 再 14 单；
- 批次 3（周末市集 + 私域回访两波）：再上架 8 件 → 再 12 次访问 → 再 14 单；
- 批次 4（工作日午间 + 直播专场两波）：再上架 8 件 → 再 12 次访问 → 再 14 单；
- 批次 5（社群团购 + 展会返场两波）：再上架 8 件 → 再 12 次访问 → 再 14 单；
- 批次 6（展会返场 + 私域复访两波）：再上架 8 件 → 再 12 次访问 → 再 14 单。
- 累计：**46 件**商品 → **70 次访问**（小红书/线下市集/私域/抖音；阿May、老周、小雅、
  程程、露露、豆豆、琪琪、楠楠等多次复访形成**复购访客 15 个**）→ **82 单**（成交 71：已付 59 +
  已退款 12；未付 11 留作口径样例）→ 12 单退款（七天无理由/错发/尺寸不合适等，验证三叠钱口径）。

## 竞赛期怎么继续跑（复现步骤）

1. 起服务（双协议确定性模型桩 + 新线实例，隔离数据目录）：
   ```bash
   STUB_PORT=8131 node stub-llm.mjs                                        # 终端 1（模型桩，罐头响应回放）
   cd .evidence-run && PORT=8130 node ../ShadowFlow-main/backend/node/node_modules/tsx/dist/cli.mjs \
     ../ShadowFlow-main/backend/node/src/index.ts                           # 终端 2
   ```
   并在实例里注册两个 byok 通道（`anthropic` 与 `custom-day1`，Base URL 均指向模型桩）。
2. 一键重演（批次 1–6 经营 + 22 会话 + 口径核对）：`python 跑数脚本-run_business.py`；
   也可只按批次照常经营（下单/项目/审批……照常走界面或 API）。
3. 导出当日材料：`python 导出脚本-export_evidence.py`（可带参：数据目录、API 基址）。
4. 逐批上传归档，40+ 小时结束后即为完整经营流水。
