## 六、口径与边界

- 营收 = 收入流水 − 退款流水；成本 = 费用流水（退款会补一条负数 expense 冲回成本）；毛利 = 营收 − 成本。
- 客单价 = 营收 ÷ 未退款成交单数；区间按记账时间切，跨期退款计入退款发生的那一段。
- 分时流水的成交额含后续退款的历史成交，与净营收口径不同，两者不相等属正常。
- 支付为演示用模拟回调，未接真实支付渠道；金额为整数分，展示时换算成元。
- 画像写回是规则式提炼（零模型消耗）；同置信不同说法记 conflict 并保留原值，不擅自覆盖。
- 本材料由已落库事实汇总生成，导出过程只读，不改写任何业务数据。
- 经营数字、画像写回流水、记忆消费留痕与协作 hop 留痕按所选统计区间；交接包与反馈队列的计数是累计全量、明细只取最近 N 条，两类口径在报告中分开标注。
- 记忆消费留痕 = 每次调用 GET /api/memory/handoff/context 读上下文时自动落的一条访问记录（谁 / 作用域 / 带出几条 / 来源），只证明「记忆被用上」，不含任何产出内容；计数为 0 只说明还没人读过，不代表功能缺失。
- 协作 hop 取自编排层已落库的 agent_hops（每条 DAG 边一行）；只记状态、产出字符数与终态原因，产出全文不落库。本材料只读汇总，不改编排层。
- 异常终态 = failed / timeout / denied / aborted / empty；返工按 detail「rework round」识别，人工审批拒绝按「审批被拒」识别；系统策略 deny 与人工审批拒绝都记为 denied，只有后者算人的决策。

## 七、复现与复用

复现步骤：

1. 一键重放：node scripts/first-order-replay.mjs --apply（默认 dry-run 只打印计划；--apply 会往当前库写 1 访客/1 单/1 支付，演示库上台前按纪律 reset）
2. 异常处理 / 老板决策演示样例：node server/node_modules/tsx/dist/cli.mjs scripts/demo-exception-replay.mjs（临时独立库造数，不碰演示库；产物带 -sample-decisions 标记，不可冒充线上导出）
3. 上台前材料自检：node server/node_modules/tsx/dist/cli.mjs scripts/demo-readiness.mjs（只读；校验产物齐全、CSV BOM、附件与看板数字一致、账实一致、第一单链路；--offline 可在没起服务时只跑材料形态）
4. 或手工复现：POST /api/merchant/products 建商品 → /visits 埋点 → /orders 下单 → /orders/:id/pay 支付
5. 打开商家数据看板核对营收/毛利，再看 /reconcile 是否账实一致
6. POST /api/memory/handoff/feedback 投递客户反馈，系统自动提炼写回画像
7. 出现同置信冲突时到「设置 — 记忆」的裁决台人工采纳或驳回
8. （可选）在已绑团队的群发消息触发 DAG：节点失败、返工与人工审批拒绝会落 agent_hops，导出时自动进入「协作执行留痕」一章
9. 在商家数据看板点「演示证据包」，分别得到评委速览一页、七章 Markdown 报告与订单 CSV
