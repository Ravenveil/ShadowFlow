赢在哪

  • 用户切换成本最低 — 点 tab 即跳，符合 Chrome/Stripe 心智模型
  • "实时跟随"和 tab 天然耦合：自动切 tab vs 用户手动切，主从关系清晰
  • tab header 自带状态 + 耗时，5 步全景仍在

代价

  • "管线"感弱 — 5 个 tab 看起来像平行页面，不是顺序流（需要在 tab 之间画 `›` 分隔符弥补）
  • 页面层级翻了一倍 — 右 pane 内已经有 Overview/Team/Agent/Preview 四 tab，现在 Agent 内再嵌 5 tab，tab 嵌 tab 反模式
  • 切到 done step 看不到 running 进度，跟随感弱化

我的偏好 — B（pipeline）打底；如果你觉得 detail 区还是太远，可以叠加 C 的"running cell 内嵌 detail" 行为做 hybrid。

关于 D（你的方案） — tab 嵌 tab 是这个方案最大的隐患：右 pane 已经有 Overview / Team / Agent / Preview 4 tab，再在 Agent 内塞 5 tab，用户会困惑"现在我点的是外层 tab 还是内层 tab"。如果想保留 tab 形态，建议把 5 步当 D 来做，但**取消右 pane 外层 4 tab**，把 Overview/Team/Agent/Preview 改成右上角下拉或左侧导航——让 tab 只在一个层级出现。这是 D 真正成立的前提。
