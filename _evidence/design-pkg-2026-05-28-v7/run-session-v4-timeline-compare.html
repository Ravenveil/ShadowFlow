三方案差异速读

  • 共同点：所有 item（user_msg / ai_text / tool_chip / step_group / code_panel / thought）共享一条垂直 rail，由 16px 圆形 marker 锚定。User 消息无气泡，直接缩进文本 + 头像点 — 这是 Trae / Codex / Cherry 的共识。
  • A · 单列时间线：step 直接以行级 rail item 渲染，最快最轻；适合 step ≤ 5 且 substep 浅。问题：step 一多就让整个 thread 视觉拉得过长。
  • B · 时间线 + 内嵌 panel：step / code 升级为 flush panel —— 没有圆角描边卡，只有 hairline 上下边 + 2px accent 竖条。仍是时间线一员，但可折叠收纳。推荐项 · 与 v3 现有 step / yaml 信息结构兼容、改动量最小。
  • C · 加左 rail 任务列表：B 之上加 52px 历史 rail，承载多 run 切换。代价：主 stream 宽度从 420 缩到 ~368，长 step 名会被截。建议当 active run ≥ 3 时才启用。
