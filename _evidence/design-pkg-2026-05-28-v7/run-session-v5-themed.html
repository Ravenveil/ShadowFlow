调研要点 · 与 v5 的映射

Trae

任务面板是消息流里的内嵌 surface 块（顶部 label「任务 · 0/3 已完成」+ 列表），而不是独立侧栏或圆角描边卡。Thought 用斜体灰阶，没有任何容器。

→ 直接映射到 方案 B 的 .fb .panel：bg-elev-1 暖灰底、顶部 uppercase mono label、不加边框。

Codex / Claude Code

字符前缀语义是核心识别符：❯ = user prompt，● = assistant headline，⎿ = tool 输出续行。这把"谁说的话"和"工具产生的回声"在零容器下分得很清。

→ 映射到 方案 A 的 .tl-user .caret、.tl-ai .bullet、.tl-echo .glyph。

Cherry Studio

仍保留传统 chat 气泡 + 模型徽章。用户提问被框成蓝色气泡、模型回复另一侧。已淘汰路径 — v3 走的就是这条，正是"割裂死板"的根源。

→ v5 全部放弃气泡；user 缩为 ❯ 前缀 + 缩进文本。

Shadow（我们自己）

Agent substep 树仍是 v5 的语义骨架：<sf:agent-substep> / <sf:edge> 协议没变，只是渲染层从「独立卡片列表」改成「时间线 entry / 内嵌块」。后端不动。

→ S6.8（substep 展开）仍生效，被吸进方案 B 的 panel 里。

推荐 / 下一步 推 方案 B（Surface 内嵌块） 替换 v3 左栏。理由：(1) 与 v3 现有 step + yaml 信息结构兼容、改动最小；(2) Trae 同款处理在 step 数 ≥ 6 时仍稳；(3) Thought / Tool chip / User msg 走方案 A 的字符前缀，A 是 B 的子集，不冲突。 实施：把 RunSessionPage.LeftPane 重构为 <ConversationTimeline>，item kind = user_msg · ai_text · tool_chip · tool_echo · step_group · code_panel · thought，每种 kind 对应一个 view 组件。预计 1 个 epic（S6.10），3 天落地。
