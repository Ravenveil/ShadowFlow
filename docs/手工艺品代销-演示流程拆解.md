# 手工艺品代销 · 演示流程拆解（对齐「AI 营销公司」组织架构图）

> 业务方向：**手工艺品代销**——对方（手工艺人）只需要上架商品，我们负责营销、
> 联系快递员寄出商品，并把订单 / 盈利 / 快递情况同步到我们平台。
> 本文按组织架构图把全流程拆成可演示、可测试的阶段，是 agent 团队搭建与
> 功能测试的执行依据。

## 一、组织架构映射（架构图 → 平台角色）

三层扁平结构，**创始人 = 董事长**（人类管理者，平台「董事长工作台」的使用者）：

| 架构图层级 | 平台角色 | 职责（架构图口径） | 交付物 |
|---|---|---|---|
| 创始人 · 人类管理者 | **董事长**（用户） | 业务目标 · 关键审批 · 资源与权限授权 | 目标下达 / 审批授权 |
| AI 总经理 CEO | **总经理**（`agent-shadow-secretary`，主控 DM） | 理解目标 · 拆解任务 · 调度员工 · 汇总结果 | 统一派单 / 成果回传 |
| 市场研究部 | **市场分析师** | 目标用户、市场、竞品和需求分析 | 用户画像 · 市场分析 |
| 品牌策划部 | **品牌策划师** | 品牌定位、产品卖点、品牌故事 | 品牌方案 · 表达规范 |
| 内容创作部 | **内容策划师** | 商品详情页、图文、短视频脚本 | 营销内容包 |
| 电商运营部 | **运营专员** | 商品资料、上架准备、店铺运营支持 | 上架清单 · 运营计划 |
| 商务拓展部 | **商务专员** | 企业采购材料、潜在客户筛选跟进 | 采购方案 · 线索记录 |
| 风控审核部 | **合规审核员** | 内容合规、授权、品牌伦理和质量检查 | 风险清单 · 审核意见 |

**汇报关系**：每名员工只向 AI 总经理汇报，不互相派单；任务经 Task API 传递
（`[dispatch]` 派活 + 群 DAG 流转），聊天仅作补充沟通。

## 二、演示流程总览（P0 → P5）

```
P0 产品接入 ──▶ P1 CEO 拆解派单 ──▶ P2 六部门执行 ──▶ P3 对外发布
  （素材→知识库）    （[build-team]/[dispatch]）  （交付物+合规打回）   （发帖·商品链接）
                                                              │
P5 汇总回传 ◀── P4 履约跟踪（订单·快递·盈利 → 平台看板同步）◀──┘
```

### P0 产品接入（董事长/卖家 ↔ AI 总经理 CEO）

| 项 | 内容 |
|---|---|
| 触发 | CEO 开场主动问「想卖什么手工艺品？」 |
| 输入 | ① 文字（产品介绍）② 图片 ③ 产品文档（txt/md/docx/pdf 等），可混发 |
| 动作 | 素材**自动同步知识库**（记忆库「手工艺品资料」pack）；文字≥10 字入库，附件（图片/文档）随消息入库；此后每轮对话自动检索知识库注入 |
| 平台同步物 | 知识库 pack（可随时调用知识库功能辅助回答和推广） |
| 退出条件 | 产品素材齐备（品名、卖点、定价三项：售价 / 成本 / 快递费） |

### P1 CEO 拆解派单

| 项 | 内容 |
|---|---|
| 动作 | CEO 理解目标 → 拆解任务 → `[build-team]` 搭建代卖团队（幂等）→ `[dispatch]` 按部门派单（to 写成员、text 写任务） |
| 团队 | 总经理 + 6 部门核心员工（见上表），团队流水线 = 架构图任务 DAG |
| 平台同步物 | 团队 / 工作群 / 任务 DAG（董事长工作台可见，可审批） |

### P2 六部门执行（含控制点）

顺序流水线（对齐架构图任务 DAG）：

```
总经理(CEO) ──▶ 市场分析师 ──▶ 品牌策划师 ──[品牌定稿·董事长审批]──▶ 内容策划师
                                                                              │
                                              运营专员 ◀─[对外发布·董事长审批]─ 合规审核员
                                                  │                    ↺ 驳回返工(≤2 次)
                                                  └──────▶ 商务专员
```

| 部门 | 做什么 | 交付物 | 业务标记 |
|---|---|---|---|
| 市场分析师 | 目标用户、市场、竞品、需求分析 | 用户画像 · 市场分析 | — |
| 品牌策划师 | 品牌定位、卖点、品牌故事 | 品牌方案 · 表达规范 | — |
| 内容策划师 | 商品详情页、图文、短视频脚本 | 营销内容包 | `[post]` 媒体平台发帖 |
| 合规审核员 | 广告法禁语 / 素材授权 / 品牌伦理 / 事实 / 质量检查 | 风险清单 · 审核意见 | 驳回（打回返工） |
| 运营专员 | 商品资料、上架准备、店铺运营、经营数据 | 上架清单 · 运营计划 | `[intake]` 上架商品、`[link]` 上商品链接、`[order]` 登记出单、`[report]` 盈利汇报 |
| 商务专员 | 企业采购材料、客户线索、**快递合作** | 采购方案 · 线索记录 | `[ship]` 联系快递员寄出 |

**控制点（架构图口径，全流程生效）**

1. 合规审核员可**打回并阻断**高风险内容（意见含「驳回」→ 内容策划师返工，≤2 次）；
2. **品牌定稿**与**对外发布**须创始人（董事长）**人工批准**（审批门，工作台批/拒）；
3. **资金操作由人负责**（agent 只出方案与登记，不执行支付/下单资金动作）。

### P3 对外发布

| 项 | 内容 |
|---|---|
| 前置 | 合规通过 + 董事长「对外发布」批准 |
| 动作 | 内容策划师在媒体平台**发帖介绍产品**（`[post]`）；运营专员**上商品购买链接**（`[link]`） |
| 平台同步物 | 社媒发布域（帖子 + 发布回执，mock/real 双模）+ 产品盈利库营销动态 |

### P4 履约跟踪（同步到我们平台）

| 环节 | 动作 | 业务标记 | 平台同步物 |
|---|---|---|---|
| 订单 | 各平台出单，按售价快照登记销售 | `[order]` | 产品盈利库订单（状态：待发货→已发货） |
| 快递 | 商务专员联系快递员上门取件寄出 | `[ship]` | 快递域发运记录（承运商 + 运单号 + 轨迹，mock/real 双模） |
| 盈利 | 运营分析师口径：盈利 = 售价 − 成本 − 快递费 | `[report]` | 产品盈利看板（盈利曲线、每卖 100 元去向） |

### P5 汇总回传

| 项 | 内容 |
|---|---|
| 动作 | CEO 汇总六部门成果（品牌、内容、发帖、订单、快递、盈利）向董事长汇报 |
| 平台同步物 | 董事长工作台汇总消息 + 商家数据看板 / 产品盈利看板 |

## 三、业务标记协议速查（agent 输出 → 平台自动落库）

标记独占一行、JSON 紧凑单行、金额单位「元」；解析后从聊天展示里剥掉：

| 标记 | 语义 | 落库 |
|---|---|---|
| `[build-team] {}` | 搭建代卖团队（幂等，CEO 专用） | 团队 + 工作群 |
| `[dispatch] {"to":"…","text":"…"}` | 向工作群派活（@成员） | 派单消息 |
| `[intake] {"name":"…","price":68,"cost":20,"shipping":8}` | 上架商品 | 产品盈利库·商品 |
| `[post] {"platform":"小红书","title":"…","text":"…"}` | 媒体平台发帖 | 社媒发布域·帖子 + 营销动态 |
| `[link] {"product":"…","url":"…"}` | 上商品购买链接 | 社媒发布域·链接帖 + 营销动态 |
| `[order] {"product":"…","qty":2}` | 登记销售出单 | 产品盈利库·销售 |
| `[ship] {"product":"…","qty":2,"tracking":"SF123"}` | 联系快递员寄出 | 快递域·发运 + 订单状态更新 |
| `[report] {"summary":"…"}` | 盈利汇报 | 运营汇报留痕 |

## 四、演示脚本（功能测试逐步走查）

1. **开场**：进入董事长工作台 → 总经理 DM 已有欢迎语（问想卖什么、说明素材自动同步知识库）。
2. **发产品素材**：发一段产品介绍文字 + 一张产品图 + 一份产品文档 → 期望：知识库「手工艺品资料」pack 出现入库记录；CEO 道谢并确认信息。
3. **定价**：回答售价 / 成本 / 快递费 → 期望：CEO 输出 `[intake]`，看板出现商品。
4. **派单**：CEO 输出 `[build-team]` + `[dispatch]` → 期望：6 部门团队与工作群自动建好，任务按 DAG 流转，各部门依次产出交付物（用户画像→品牌方案→营销内容包→风险清单→上架清单→采购方案）。
5. **审批门**：品牌定稿、对外发布两次挂起等董事长批准 → 期望：工作台出现审批卡，批准后流水线继续；拒绝则停在原地。
6. **发布**：批准后内容策划师 `[post]` 发帖、运营专员 `[link]` 上链接 → 期望：社媒发布域出现帖子与发布回执。
7. **履约**：订单管家环节 `[order]` 出单 → 商务专员 `[ship]` 联系快递员寄出（运单号）→ 期望：订单状态「待发货→已发货」、快递域出现发运与轨迹。
8. **盈利**：运营分析师 `[report]` 盈利汇报 → 期望：产品盈利看板长出盈利曲线与去向拆解，商家看板数字一致。
9. **汇总**：CEO 最后向董事长汇报全链路成果。

## 五、已知边界（演示口径）

- 社媒发布 / 快递承运默认 **mock 模式**（确定性回执与运单号，不发外网）；接真实平台/承运商签约账号后按同一接口切 `real`。
- 资金操作（支付、结算）不由 agent 执行，只出方案与登记。
- 定价信息由界面固定提问卡收集，agent 不重复追问。

## 六、演示验证记录（2026-11-08 全流程实测）

以「苗绣杯垫」（售价 68 / 成本 30 / 快递 8，龙奶奶手作）实测 P0→P5 全链路，
LLM 走 MiMo（`byok:mimo`，模型 `mimo-v2.6-pro`），验证结果：

| 环节 | 验证点 | 结果 |
|---|---|---|
| P0 产品接入 | 文字+图片+文档自动同步知识库 | ✅ pack「手工艺品资料」，多轮对话素材持续入库 |
| P1 拆解派单 | `[build-team]` 建团队（幂等）+ `[dispatch]` 派单 | ✅ 7 人编制 + 工作群自动创建；6 部门派单消息逐条落群；重复触发返回「复用」 |
| P2 六部门执行 | DAG 流水线 + 交接链 | ✅ 交接记录 6 次交接全 ✅（最后一轮）；各部门产出交付物（调研简报/品牌口径/内容包/审核红线/上架清单/投放方案） |
| P2 审批门 | 品牌定稿、对外发布两道人工审批 | ✅ 挂起→批准→流水线继续，全流程出现两次并生效；拒绝路径会跳过节点并拦截下游交接 |
| P3 对外发布 | `[post]` 发帖 + `[link]` 上链接 | ✅ 社媒发布域 2 条 published（小红书帖文《一张一纹，龙奶奶手作的苗绣杯垫》+ 购买链接帖），mock 回执 `mock_xiaohongshu_*` |
| P4 履约跟踪 | `[order]` 出单 → `[ship]` 寄出 | ✅ 销售 2 件、状态 shipped、运单 SF20261108001；快递域顺丰 mock 面单 SF115185506023（含收件人/电话/地址），订单状态「待发货→已发货」 |
| P4 盈利 | `[report]` 盈利汇报 | ✅ 汇报 2 件毛利 60 元（毛利率 44.1%）；产品盈利库商品/销售数据与看板口径一致 |
| P5 汇总回传 | CEO 全链路汇报 | ✅ 《全链路成果汇总 · 苗绣杯垫》回传董事长（发布/上架/订单/物流/盈利/合规六节） |

**演示注意事项**

1. 董事长口径确认类消息宜一次性拍板（"直接执行不要再确认"），否则 agent 会按记忆偏好先来一轮范围确认；
2. 工作群 @ 提及的可点名成员名单含 5 人（总经理/市场分析师/品牌策划师/内容策划师/合规审核员），
   @运营专员、@商务专员 不会命中 @ 匹配、按全员广播派发（任务仍由 DAG 路由到岗）；
3. `[intake]` 多轮重复登记会产生重复商品行（演示中商品出现 2 条同名记录，其中 1 条 0 销量），正式版需加去重/合并；
4. byok 配置必须以 **JSON 字符串值** 存入 `settings.json`（`{"byok": "{\"providers\":…}"}`），
   嵌套对象会被 `load()` 丢弃导致 executor 回落 `cli:claude`；推荐走 `PUT /api/settings/byok/:id`。
