### 第一阶段：识别核心概念

#### 论文的 Motivation 分析

现代 AI Agent 依赖复杂的推理框架（Inference Harness，例如 Claude Code、Codex、OpenClaw 等）驱动多轮推理、工具调用及外部系统交互。然而，复杂的 Harness 使得 Agent 难以在开源基础设施上进行端到端的训练：

• **训练与部署严重脱节**：开源 SFT/RL 框架（如 veRL、Slime 等）无法原生表达带有状态、多进程的复杂 Harness 逻辑。既有开源工作往往需要重构简化版的 Harness 用于训练，导致训练与实际部署环境不一致。

• **环境隔离与弹性扩缩容困难**：复杂 Harness 的运行需要独立的容器化沙盒（配备专用 CPU、内存及 GUI 渲染环境），无法与训练 GPU 节点同机部署。开源 RL 框架普遍假定 Rollout 在本地节点完成，无法弹性扩展到成百上千个远程云端环境。

OPENFORGE RL 旨在打破这一瓶颈，提供一个将任何部署 Harness 与任何沙盒环境连接到标准开源 RL 框架的解耦基础设施。

#### 论文主要贡献点分析

• **OpenForge RL 基础设施框架**：提出了一个轻量级代理（Proxy）结合云端 Kubernetes 编排器的插件式架构，将底层的 RL 策略训练器与上层的复杂 Harness 及远程沙盒完全解耦。

• **数据与环境合成管线**：构建了自动化的任务、沙盒环境与校验器（Verifier）合成管线，覆盖每日工具/Claw 任务、计算机 GUI 操作及浏览器操控等领域。

• **显著的性能提升**：

◦ **OpenForge-Claw（30B-A3B MoE，约 3B 激活参数）** 在 ClawEval 上达到 31.7（pass³）和 55.9（pass@3），在 QwenClawBench 上达到 33.7，显著超越同等体量的开源基线。

◦ **OpenForge-GUI（8B）** 在 OSWorld-Verified（37.7）、Online-Mind2Web（63.0）及 WebVoyager（72.3）上均领先论文列出的同等规模开源基线。

• **Harness 与 RL 行为学分析**：系统探讨了 Harness 复杂度对 Agent 可学习性的影响，证明了多 Harness 混合训练能大幅提升跨 Harness 泛化能力，并阐明了 RL 对 Agent 行为可靠性（如自我验证、工具覆盖度）的增强机制。

#### 理解难点识别

• **原生 Harness 训练（Harness-Native Training）**：直接在真实的部署框架内部训练模型，而非在简化重构的模拟环境中训练。

• **基于代理的轨迹解耦与重构（Proxy-based Trajectory Reconstruction）**：拦截远程容器发出的 API 请求，将多进程、多轮次交互还原为符合标准 RL 算法要求的样本序列。

• **远程容器化 Rollout 编排（Remote Containerized Rollout Orchestration）**：在云端动态调度与生命周期管理大规模隔离沙盒容器。

#### 概念依赖关系

环境与 Harness 运行于远程容器中  轻量代理拦截 Harness 发出的模型生成请求并转发至推理引擎  收集终端奖励并重构轨迹样本  标准 RL 训练器（如 veRL）接收重构轨迹并更新策略梯度。

### 第二阶段：深入解释核心概念

#### 生活化比喻设计：智能驾考系统与中央控制中心

将 Agent 的训练过程比作一个**现代化智能驾考培训中心**：

• **考生（Agent 模型）**：正在接受培训的驾驶决策大脑。

• **汽车驾驶舱控制系统（Harness）**：包括方向盘、仪表盘、自动挡控制器和倒车雷达等组件。不同车型的驾驶舱界面和交互复杂度不同（如普通自动挡车与赛车控制台）。

• **封闭测试考场（远程沙盒容器）**：位于异地的真实物理考场，包含红绿灯、路障和天气系统。

• **车载黑匣子代理（Proxy Server）**：安装在考试车上的智能通信中继器，实时拦截考生的所有打方向盘和踩刹车动作，透传给中央控制室并记录全过程。

• **中央教练组（RL 训练器）**：坐在远端监控室里，接收黑匣子传回的操作日志与考试成绩，批量更新考生的“驾驶手册”（策略权重）。

#### 比喻与实际技术的对应关系

|比喻元素|实际技术概念|合理性解释|
|---|---|---|
|**考生**|策略模型（Policy Model）|负责接收观察并输出动作决策|
|**驾驶舱控制系统**|推理框架（Harness）|加工原始环境观察并管理多轮工具交互|
|**异地考场赛道**|远程容器沙盒（Remote Pod）|提供隔离的真实执行环境（如 Linux/GUI）|
|**车载黑匣子代理**|轻量代理服务器（Proxy Server）|解耦训练与执行，透明拦截并记录交互数据|
|**中央教练组**|RL 训练器（如 veRL）|基于轨迹样本和最终成绩计算梯度并更新权重|

#### 深入技术细节与公式拆解

OPENFORGE RL 在 Rollout 结束时，由 Proxy 收集终端任务奖励 ，并将拦截到的交互对重构为适合 RL 训练的轨迹 ：

**数学符号与自然语言映射对照**：

• ：完整训练轨迹 = 一次任务执行中所有历史步骤的有序集合。

• ：Harness 上下文状态 = 第  步时经由推理框架加工后喂给策略模型的观察与上下文。

• ：策略模型动作 = 第  步时模型生成的具体回复或工具调用指令。

• ：折算步骤奖励 = 将终点任务奖励按  分配至第  步；论文通常取 。

• ：终端奖励分配项 = 折扣系数的  次方乘以最终任务完成状态的终端奖励。论文默认  时，各步得到相同的终端奖励，并不存在时间衰减。

#### 技术细节与比喻的相互映射

• **上下文生成（）**：驾考时，仪表盘（Harness）将路面传感器数据整理成驾驶员能看到的界面。

• **动作拦截（）**：考生踩下刹车（生成动作），黑匣子代理（Proxy）记录该动作并将其透传给车辆执行。

• **终端奖励折算（）**：考试结束后考官给出总分（），黑匣子将其回溯分配到此前每一个弯道（第  步）；论文通常取 ，所以这些步骤获得相同的终端奖励，而非随时间衰减。

• **局限性**：在仅提供二值化终端奖励（0 或 1）的情况下，这种折算无法精确区分长流程操作中的具体中间失误。

#### 核心联系总结

通过黑匣子 Proxy 的拦截与重构，中央教练（RL 训练器）无需关心车辆内部控制回路（Harness 内部复杂逻辑），也不必将物理考场搬入监控室（GPU 训练节点与执行环境物理隔离），只需处理标准格式的数据即可完成策略优化。

### 第三阶段：详细说明流程步骤

#### 步骤 1：环境初始化与调度

• **输入**：任务描述（Task Instruction）、目标环境的 Dockerfile、目标 Harness 配置。

• **处理过程**：Kubernetes 编排器在云端部署独立的沙盒 Pod，预装指定的 Harness（如 OpenClaw、Codex 或 Kimi-Agent）以及执行环境（如桌面 GUI 或 Linux Shell）。

• **输出**：已就绪的远程容器沙盒实例。

#### 步骤 2：请求拦截与路由

• **输入**：沙盒内 Harness 生成的初始 Prompt 。

• **处理过程**：Harness 向预设 API 地址发出生成请求，被 OPENFORGE RL 的 Proxy 拦截。Proxy 记录 Prompt ，并将请求转发至分布式推理引擎（如 vLLM）。

• **输出**：策略模型生成的动作 （如工具调用指令或键盘鼠标动作）。

#### 步骤 3：多轮交互与状态更新

• **输入**：推理引擎输出的动作 。

• **处理过程**：Proxy 将  返回给沙盒内的 Harness 执行。Harness 在沙盒环境中运行该动作，捕获新的环境状态，更新内部上下文并生成 。此过程反复循环直到任务完成或超时。

• **输出**：全套交互序列与校验器返回的终端奖励 。

#### 步骤 4：轨迹重构与优势估计

• **输入**：拦截的交互序列及终端奖励 。

• **处理过程**：Proxy 的轨迹重构模块根据公式  计算每一步的折算奖励，并按组（Group）汇总轨迹以计算相对优势值（Advantage）。

• **输出**：符合标准 RL 框架（如 veRL）接口规范的数据 Batch。

#### 步骤 5：策略梯度更新

• **输入**：重构完成的 RL 数据 Batch。

• **处理过程**：训练器按所选 RL 算法计算损失、执行反向传播并更新策略模型权重，再同步至推理引擎。论文框架本身与算法无关，文中实验具体采用 GRPO。

• **输出**：更新后的策略网络权重。

### 第四阶段：实验设计与验证分析

#### 主实验设计解读

#### **数据集与评估基准**

• **Claw/工具调用领域**：选用 ClawEval（综合评估）、QwenClawBench（真实 OpenClaw 分布）及 MCPAtlas（默认 20 个 MCP 服务器配置，对应 89 个可完整支持的任务）。评估指标包含 `pass³`、`pass@3` 与 `pass@1`。

• **GUI 操控领域**：选用 OSWorld-Verified（计算机桌面）、Online-Mind2Web（真实 Web 操控）及 WebVoyager（长流程网页探索）。评估指标为 `pass@1`。

#### **基线选择**

• 同等参数量级别的开源基线：LLaMA-4-Scout-17B、Mistral-Small-3.1-24B、Qwen3-30B-A3B-Thinking、Qwen3-Coder-30B-A3B-Instruct、UI-TARS-1.5-7B、OpenCUA-7B、MolmoWeb-8B 等。

• 顶尖闭源模型参考：Claude Opus 4.6、GPT 5.4、Gemini 3.1 Pro。

#### **核心实验结果**

• **Claw 领域**：OpenForge-Claw（30B-A3B MoE，约 3B 激活参数）在 ClawEval 上达到 31.7（pass³），显著超越基线 Qwen3-30B-A3B-Thinking（14.3）与 Qwen3-Coder-30B-A3B-Instruct（30.4）。在 MCPAtlas 上达到 28.1。

• **GUI 领域**：OpenForge-GUI（8B）在 OSWorld-Verified 上取得 37.7 的成绩，大幅领先 UI-TARS-7B（27.4）与 OpenCUA-7B（28.2）；在 Online-Mind2Web 达到 63.0，超越 MolmoWeb-8B（35.3）。

• **RL 增益验证**：在所有 Benchmark 上，SFT+RL 均在单纯 SFT 基础上取得了显著的二次提升。

#### 消融实验与多 Harness 混合训练分析

#### **跨 Harness 泛化评估（Table 5）**

• **实验设计**：比较在单一 Harness（ZeroClaw）上训练的模型，与在多种 Harness（ZeroClaw + OpenClaw + Codex）上混合训练的模型，并在未见的 Harness 上进行测试。

• **实验数据**：

◦ 单 Harness 训练具备跨 Harness 泛化能力：仅在 ZeroClaw 上训练，在未见的 OpenClaw 上成绩由 11.4 提升至 14.7（+3.3），Codex 由 12.2 提升至 16.8（+4.6）。

◦ **多 Harness 混合训练表现最佳**：多 Harness 混合训练后，ZeroClaw 达到 48.5（+16.0），OpenClaw 达到 20.9（+9.5），Codex 达到 32.5（+20.3）。

#### 深度/创新性实验剖析

#### **工具选择偏好转移分析（Figure 5a / Figure A5）**

• **实验设计**：统计 SFT 与 SFT+RL Checkpoint 在 ClawEval 上的工具调用频次分布。

• **实验结论**：SFT 模型过度依赖通用 `shell` 工具（占比 22.6%）。经过 RL 训练后，`shell` 调用占比下降至 **13.9%**（成功轨迹中仅占 **5.6%**），调用的动作被重新分发给专用的服务 API（如 `contacts_search`、`gmail_get_message` 等）。

#### **Agent 行为能力雷达图分析（Figure 5b）**

• **实验设计**：在 Codex Harness 下评估 5 项 Agent 行为维度。

• **定量结论**：

◦ **自我验证（Self-verification）**：由 SFT 的 42% 提升至 **60%**，模型学会在写操作后主动进行检查。

◦ **工具覆盖度（Tool Coverage）**：由 54% 提升至 **81%**，长流程计划完成能力增强。

◦ **错误恢复（Error Recovery）**：虽由 17% 提升至 **26%**，但整体依然偏低，表明单凭终端奖励 RL 难以充分学会错误恢复能力。
