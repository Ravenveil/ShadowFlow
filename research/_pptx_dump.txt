01 · 问题
梯度优化万物，止于"不可微"
AutoDiff 的世界（PyTorch）
真实的 AI 工作流

· 计算图可微分：每个算子有解析梯度
· 反馈是标量损失：一个数代表好坏
· 参数同质：全是浮点张量
· 结构静态：图在编译期固定
反向传播把误差沿图回传，每个参数得到精确改进方向——这套机制支撑了十亿参数级网络的端到端优化。
· 不可微：LLM 调用、工具调用、模拟器、检索
· 反馈丰富：控制台输出、用户回复、编译报错
· 参数异质：提示词、代码、超参混在一起
· 结构动态：编排逻辑随输入改变图的形状
部署后行为出错只能靠工程师手动改；贝叶斯优化 / 进化算法 / RL 只吃标量反馈，在大参数空间效率极低。

研究问题：能否找到一种载体，替代梯度，把"输出的丰富反馈"端到端地归因到"异质参数"上？作者的回答：执行轨迹（execution trace）。

01 · 核心洞察
执行轨迹 ≈ 不可微系统的"梯度"
工作流视作计算图：节点是输入 / 参数 / 计算结果，边是"谁由谁计算而来"。反向传播传播梯度；Trace 传播执行轨迹。
① 轨迹记录了"中间结果如何被使用"
这是把输出端反馈归因到上游参数所需的全部信息。
② 严格包含反向传播
论文证明：可微分情形下，传播轨迹的 backward 就是梯度反传——AutoDiff 是 Trace 的特例。
③ 对不可微工作流仍然成立
LLM、代码、模拟器无所谓"梯度"，但都有执行轨迹——人类工程师本来就用轨迹 debug 分布式系统。
④ 最小子图控制成本
只把与参数有因果关系的子图交给优化器，等价于只回传相关梯度。

前向：执行工作流，记录轨迹

输入 map

参数 θ

中间结果

输出 + 反馈 f

回传：最小子图 g + 反馈 f（而非梯度 ∇）

02 · 形式化
OPTO：带轨迹预言机的迭代优化
OPTO 问题实例 = 三元组 (Θ, ω, T)
· Θ：参数空间（提示词 / 代码 / 超参）
· ω：问题上下文（任务说明、环境描述）
· T：Trace Oracle，输入 θ，返回轨迹反馈
一轮 OPTO 迭代

① 优化器选择参数 θ（如改写后的提示词）

② Trace Oracle 执行工作流，返回 τ = (f, g)

f = 对输出的反馈（自然语言 / 标量 / 控制台输出）
g = 以 θ 为输入的执行计算图（含全部中间值）
对照：传统优化只给 f（标量），OPTO 同时给"问题是怎么算出来的"。

③ 优化器依据 f 与 g 更新 θ → 进入下一轮
与相邻概念的关系：OPTO 像 RL，但反馈不是标量奖励而是"丰富反馈 + 轨迹"；像贝叶斯优化，但不把系统当黑箱；像 AutoDiff，但不要求可微。它是一个新的数学 setup，而不是某个具体算法。

02 · 系统
Trace 库：像写 PyTorch 一样声明可优化工作流

与 PyTorch 的一一对应
# Battleship 智能体策略
class Policy(trace.Module):
  def forward(self, map):
    plan = self.reason(map)
    return self.act(map, plan)

  @trace.bundle(trainable=True)
  def reason(self, map): ...

policy = Policy()
optimizer = trace.Optimizer(
    policy.parameters())
# 与环境交互 → 收集轨迹 → 更新
| PyTorch | Trace |
| --- | --- |
| Tensor | Node（任意对象：字符串 / 代码 / 数值） |
| nn.Module 层 | @bundle 装饰的算子 |
| requires\_grad=True | trainable=True |
| SGD / Adam | LLM 优化器（OptoPrime） |
图 1 · 基于论文 Fig. 2 简化：trainable 标记即"可训练参数"
关键差别只在最后一行：优化器从"数值算法"换成了"读轨迹的 LLM"——更新的可以是 prompt 的措辞，也可以是整段 Python 代码。

02 · 优化器
OptoPrime：让 LLM 像程序员一样"读轨迹改代码"
一份真实的伪代码报告（论文 Fig. 4）
执行工作流
记录每个算子的输入输出，得到完整执行轨迹。

①

#Code
a = bar(x); y = add(b, a)
z = mul(a, y)
#Inputs: b=1.0
#Others: a=2.0  y=3.0
#Output: z=6.0
#Variable: x=-1.0
#Feedback: Output should be larger.
提取最小子图
只保留与可训练参数有因果关系的节点，压缩 token。
②
转写为伪代码报告
子图 → "代码 + 算子说明 + 各变量取值 + 反馈"的文本报告。
③
LLM 推理并更新参数
像 debug 一样推断"改哪个参数、往哪个方向改"，输出新 θ。
④
LLM 读到"z 要更大、a=x 的负缩放、x 是变量"，即可推出应把 x 调得更负——无需任何梯度。

03 · 边界
局限：作者自己划出的三条边界

已被证明的
尚未解决的
· 轨迹传播严格包含反向传播（可微情形）
· 单一 OPTO 接口覆盖五个问题类
· 丰富反馈（自然语言）可作为有效优化信号
· 中等规模图上 OptoPrime 稳定工作
① 反馈设计成为新的"损失函数设计"
反馈怎么设计、最优性如何定义，是开放研究问题。
② 表达边界
原地修改状态的有状态函数无法直接表示为 DAG；分布式 / 并行工作流与当前实现不兼容（理论上无环即可异步）。
③ OptoPrime 只是初步方案
非可证最优；token 开销大于 OPRO；问题规模受限于 LLM 的 debug 能力与上下文长度。
对我们的含义：第②条意味着 Trace 目前管不了"万级 agent 并行仿真"本身——它优化的是单个工作流的参数；并行仿真需要另一层（DES 内核），两者是互补关系。

04 · 视角一：控制论
OPTO 就是一个反馈控制环
| PDCA | 控制论角色 | OPTO 对应物 |
| --- | --- | --- |
| Plan | Setpoint 设定值 | 目标 / 上下文 ω |
| Do | Actuator 执行器 | 工作流以 θ 执行 |
| Check | Sensor 传感 | 反馈 f + 轨迹 g |
| Act | Controller 控制律 | OptoPrime 更新 θ |
好调节器定理 → 世界模型
"Every good regulator of a system must be a model of that system."
—— Conant & Ashby, 1970
· Alicea et al. (2025) 把这一定理对接到现代 AI：能调控系统的智能体，其内部必然含有该系统（近似）的世界模型。
· 对金融世界模型的推论：央行 agent 的调控能力上界 = 它内部模型的质量——世界模型不是奢侈品，是调控的前提。
· 智能体的信念更新（belief update）= 内部模型的在线修正；反馈设计决定模型修正的方向。
表 2 · OPTO 迭代的控制论拆解（对照 ShadowFlow 循环引擎 §1.2）
ShadowFlow 侧的资产：循环引擎（loop_engine.py）已实现 PDCA↔控制环映射、Sensor/Controller 一等节点、loops-watching-loops 监督（VSM System-2）、分形嵌套上界。缺的正是 Trace 补的东西：把 Sensor 读到的轨迹反馈转成 Controller 的参数更新。

04 · 视角二：博弈论
均衡 = "没有有利可图的偏离"
把多智能体系统写成随机博弈

EGTA：经验博弈论分析
· 状态随联合动作演化 → Markov Game / 随机博弈
· 每个 agent 的最优性 = 给定他人策略时的最优反应（best response）
· 经验均衡检验：固定他人策略，看单 agent 偏离是否还能获益（ε-Nash）
仿真估计收益矩阵 → 在策略子空间求解纳什均衡 → 用新发现的策略扩充博弈，迭代收敛。
ABIDES 主论文的 spoofing 研究即此方法（Wellman 学派）。
ABIDES-Economist 的实测规模
· 10,503 个规则 agent / 单步约 5,000 万条消息 / 约 20 分钟跑完
· RL 学习只敢做 112 个 agent；4 个类型级共享策略网络
· 共享策略 = 对称马尔可夫完美均衡假设，同时充当均衡选择机制
· 训练 4.3 万 episode / 31 小时（PPO + RLlib 并行采样）
万级规模：平均场博弈
· N 人博弈不可分析 → 近似为"一人对群体分布"
· 观测从"逐 agent"变"分布统计量"，通信 O(N²)→O(N)
· 既是性能工具，也是理论接口（MFG 均衡可证）
要点："均衡"不是算出来的解析解，而是用轨迹反复检验"偏离是否有利可图"得到的经验结论——这就是下一页的结合点。

参考：arXiv:2601.15047 · arXiv:2205.12944 · arXiv:2402.09563（§4.3.3）

### Notes:

04 · 研究切口
提案：Trace 驱动的经验博弈均衡分析

① DES 仿真
万级 agent 市场仿真，产出完整执行轨迹
② 轨迹优化
OPTO：轨迹+反馈做生成式 best-response
③ 均衡探测
检验偏离是否仍有利可图（ε-Nash）
④ 调控检验
好调节器定理检验央行内部模型

发现更优策略 → 扩充博弈 → 回到①重新仿真（EGTA 式迭代）
与主流 MARL 路线的差异
· 不依赖奖励函数设计：反馈可以是市场评论、风控警告、合规驳回等自然语言信号（回应启动会"结果高度依赖奖励函数"的痛点）
· 可解释：每次参数更新附带 LLM 的归因推理，而非黑箱梯度步
· 与规模解耦：优化只发生在"关键角色"的轨迹上，背景种群保持廉价规则 agent
ShadowFlow 的现成资产：RunTrajectory / TrajectoryBundle 契约已有 Trace 所需的轨迹数据结构；rejection loop 与策略矩阵天然是"丰富反馈源"；循环引擎提供 PDCA 骨架。补 DES 内核 + OPTO 优化层即闭环。
