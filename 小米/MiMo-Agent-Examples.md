# MiMo Agent 编排样例 ×10

> 用途：JUNCTION CHINA 2026「OPC · 一人公司」赛题技术支持包
> 每个样例 = 一种编排模式 + 一个一人公司场景。选手可直接照抄结构，换自己的业务。
> 模型：MiMo-V2.6-Pro（Tool Use / 多智能体 / 1M 上下文 / 多模态 / 代码 / 办公 / 设计 / 科研 / 创作 / 网络安全 / 电脑操控）

---

## 1. 商品上架流水线（串行 Pipeline）

**场景**：一人电商小店，把一批新货从「一张图」变成「可售卖链接」。

**编排**：`视觉理解 → 文案生成 → 定价策略 → 页面上架 → 客服话术`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 识品 | 读商品图，输出品类/卖点/风险点 | 多模态 |
| 文案 | 生成标题、详情页、卖点短文案 | 创作 |
| 定价 | 结合成本表与竞品价给定价建议 | 复杂推理 |
| 上架 | 调用平台 API 或操作浏览器完成上架 | Tool Use / 电脑操控 |
| 客服 | 预生成 FAQ 与应答模板 | 办公 |

**最小交付**：输入 3 张商品图，输出 3 条可访问的商品页 + 定价说明 + FAQ。
**编排要点**：每级输出结构化 JSON，失败可从任意节点重跑。

## 2. 内容工作室（主管-执行者 Supervisor-Worker）

**场景**：一人自媒体，一周的内容从选题到分发。

**编排**：`主编 Agent 拆解任务 → 写手/设计/剪辑 Agent 并行 → 主编汇总裁稿`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 主编 | 定选题、拆任务、终审把关 | 复杂推理 |
| 写手 ×2 | 并行写长文 / 短帖 | 创作 + 1M 上下文 |
| 设计 | 出封面与配图需求，生成视觉稿 | 设计 + 多模态 |
| 剪辑 | 生成分镜与口播脚本 | 视频理解 |
| 发布 | 排期并投递到各平台 | 电脑操控 |

**最小交付**：一次输入主题，输出 1 篇长文 + 2 条短帖 + 1 张主视觉 + 发布排期表。
**编排要点**：主编是唯一对外出口，执行 Agent 不得直接改最终稿。

## 3. 独立开发者发版（评审循环 Critic Loop）

**场景**：一人开发，把一个功能从需求做到可发布。

**编排**：`实现 → 自测 → 评审打回 → 修复 → 发布说明`（可循环 N 次）

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 实现 | 写代码、补测试 | Coding |
| 测试 | 跑用例、复现 Bug | Coding + Tool Use |
| 评审 | 按清单挑安全/性能/可维护问题 | 复杂推理 + 网络安全 |
| 发布 | 生成 changelog、打 tag | 办公 |

**最小交付**：给定一个小需求，仓库里有代码 + 测试全绿 + 一份发布说明。
**编排要点**：评审 Agent 持有「否决权」，最多 3 轮，防止空转。

---

## 4. 自由顾问投标（路由分发 Router）

**场景**：一人咨询工作室，处理进来的客户需求。

**编排**：`接待分类 → 分发到顾问 Agent → 汇总报价与提案`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 接待 | 读懂需求，判定类型/紧急度/预算 | 复杂推理 |
| 行业顾问 ×3 | 按行业（消费品/制造/教育）出方案草稿 | 科研 + 1M 上下文 |
| 商务 | 工作量评估、报价单、合同要点 | 办公 |
| 风控 | 检查承诺风险、合规红线 | 网络安全 / 风控 |

**最小交付**：输入 1 封客户需求邮件，输出分类标签 + 提案草稿 + 报价单 + 风险清单。
**编排要点**：Router 只做分发与置信度判断，置信度低时走人工确认。

## 5. 活动主办方（并行扇出 Fan-out）

**场景**：一人公司办一场线下沙龙 / 发布会。

**编排**：`统筹 Agent 一次拆解 → 邀请/物料/议程/传播 四路并行 → 统筹合流`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 统筹 | 拆任务、卡节点、催进度 | 办公 |
| 邀请 | 写邀请函、生成嘉宾名单话术 | 创作 |
| 物料 | 海报文案、物料清单 | 设计 |
| 议程 | 时间表、主持稿 | 办公 |
| 传播 | 通稿、社媒倒计时 | 创作 |

**最小交付**：一份执行手册（议程 + 邀请函 + 物料清单 + 传播排期）。
**编排要点**：四路并行，各写各的文件夹，最后统筹只做拼装与冲突消解。

## 6. 知识付费课堂（长上下文中枢 Context Hub）

**场景**：一人讲师，把一门课从原始资料做到可售卖。

**编排**：`资料全量吞入 1M 上下文 → 大纲/课件/作业/答疑 共享同一份「课程大脑」`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 图书馆员 | 吃进书稿、论文、往期问答，建索引 | 1M 超长上下文 |
| 课程设计 | 大纲、章节目标 | 教研 / 科研 |
| 课件 | 讲义、板书、示例 | 创作 |
| 出题 | 习题与答案解析 | 复杂推理 |
| 答疑 | 基于同一份资料回答学员问题 | 1M 上下文 + 记忆一致性 |

**最小交付**：输入一叠课程资料，输出大纲 + 2 讲讲义 + 1 套习题 + 可演示答疑。
**编排要点**：所有 Agent 共享同一 Context Hub，禁止各自检索、各说各话。

## 7. 客服值守（人机协作 Human-in-the-Loop）

**场景**：一人公司接客服，7×24 不漏单、关键节点要人拍板。

**编排**：`自动应答 → 风险判定 → 升级给人类老板 / 自动结案`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 前台 | 多轮应答、情绪识别 | 多模态（语音可选） |
| 质检 | 识别投诉/退款/舆情风险 | 复杂推理 |
| 升级官 | 生成处置建议，推送给「老板」审批 | 办公 |
| 工单 | 记录、回访、归档 | 办公 / 电脑操控 |

**最小交付**：20 条模拟会话中，普通单自动结案、高风险单正确升级并留下工单。
**编排要点**：所有「钱、法律、舆情」必须经人类确认，流水线只准备材料、不做终裁。

## 8. 一人公司经营周报（跨系统操盘 Computer Use）

**场景**：每周自动把散落在各处的经营数据整理成老板看得懂的周报。

**编排**：`采集 → 清洗 → 分析 → 成文 → 发出`，采集端真实操作浏览器/表格/邮件

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 采集员 | 操作浏览器与本地文件取数 | 电脑操控 |
| 会计 | 票据、收支、毛利 | 办公 |
| 分析师 | 环比、异常、归因 | 复杂推理 |
| 秘书 | 生成一页纸周报 + 3 条决策建议 | 创作 / 办公 |
| 发送 | 邮件或群消息发出 | Tool Use |

**最小交付**：真实读取至少 3 个来源（表格/网页/邮件），输出一页纸周报并成功发出。
**编排要点**：采集 Agent 必须留痕（截图/日志），保证结果可复核。

## 9. 跨境小店本地化（多语多模态产线）

**场景**：一人跨境卖家，把商品内容从中文做成英语 / 西语市场可投物料。

**编排**：`本地化策略 → 翻译改写 → 合规检查 → 素材适配 → 多语客服包`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 策略 | 目标市场卖点与禁忌 | 科研 |
| 译创 | 不是直译，按市场重写卖点 | 创作 |
| 合规 | 广告法/平台禁词/标签检查 | 网络安全意识 / 风控 |
| 素材 | 根据市场改图、改视频脚本 | 多模态 + 设计 |
| 客服包 | 多语 FAQ 与退换货话术 | 办公 |

**最小交付**：1 个中文商品 → 2 个语种的完整上架包（文案 + 素材需求 + 合规检查单）。
**编排要点**：合规 Agent 一票否决，改写必须基于策略 Agent 的市场设定，避免漂移。

## 10. 风险雷达（监测-研判-行动 Sense-Think-Act）

**场景**：一人公司做品牌，自动盯舆情、竞品与安全风险，出应对动作。

**编排**：`监听 → 研判 → 生成应对 → 等待确认 → 执行`

| Agent | 干什么 | MiMo 能力 |
|---|---|---|
| 监听 | 定期抓公开信息、竞品动态、账号异常 | 电脑操控 |
| 研判 | 区分噪音/机会/风险，定级 | 复杂推理 |
| 参谋 | 给 2–3 套应对方案与话术 | 创作 / 办公 |
| 执行 | 发声明、改文案、开权限工单 | Tool Use |

**最小交付**：注入 5 条模拟事件，其中 1 条危机、1 条机会，输出定级与应对动作并执行其一。
**编排要点**：Sense / Think / Act 严格分离；Act 一律先过人类确认闸门。

---

## 怎么用这些样例

1. **选一个场景当壳**，别自己从零发明公司形态。
2. **编排模式比 Agent 数量重要**——评委看的是「谁向谁汇报、出错谁兜底」。
3. **把不可逆动作放进人工闸门**（付款、发声明、删数据），这反而是加分项。
4. **演示脚本 3 分钟**：进 → 出 → 中间一次失败重试，比全流程完美更有说服力。

> 建议主推演示组合：**#1 流水线（好懂）+ #3 评审循环（显工程）+ #7 人机闸门（显成熟）**，覆盖「干活、对质量、担责任」三层。
