# 场景一 · 跨境一人小店（Global Gadget）

## 1. 公司画像

一个人经营 3–5 款设计型小商品，卖到海外（独立站 / Etsy / 亚马逊）。卖的不是「便宜货」，是「有设计感的小东西」。

**第一单定义**：1 个 SKU 完成上架 → 真实或模拟支付成功 → 生成发货单与物流单号。

## 2. 全流程总表

| 阶段 | 目标 | 本场景专属交付物 |
|---|---|---|
| 0 立案 | 选品类、选市场、算得过账 | 品类机会表、目标市场（欧美/东南亚）、单件毛利模型（货+运+平台费+汇率） |
| 1 开张 | 有店、有品牌、合规 | 店名与 VI、店铺/独立站、支付开通、标签与隐私合规清单 |
| 2 产品 | 有货可卖 | 供应商沟通记录、商品档案、包装/标签图、详情页 |
| 3 营销 | 被看见 | listing 文案、SEO 词表、社媒种草帖、小预算投放计划 |
| 4 成交交付 | **第一单** | 订单、付款凭证、发货单、物流单号、面单 |
| 5 售后 | 不炸店 | 多语 FAQ、退换流程、差评应对话术 |
| 6 财务 | 知道赚不赚 | 平台结算单、汇率损益、单件真实毛利、补货资金表 |
| 7 复盘 | 决定加什么砍什么 | SKU 动销榜、广告 ROI、补货/淘汰决策 |

## 3. 专属 Agent 编排

| Agent | 职责 | MiMo 能力 |
|---|---|---|
| 选品官 | 品类趋势、竞争密度、运费敏感性分析 | 科研 + 推理 |
| 成本会计师 | 产品+头程+尾程+平台费+汇率全成本建模 | 办公 + 推理 |
| 供应商联络员 | 询价、打样要求、最小起订量谈判邮件 | 办公 + 创作 |
| Listing 专员 | 标题/五点/详情/A+，含 SEO 词 | 创作 + 多模态 |
| 视觉组 | 主图、场景图、尺寸图需求单 | 设计 + 多模态 |
| 投放手 | 小预算测试计划、关键词、出价 | 复杂推理 |
| 多语客服 | 尺码/时效/退换，英/西/德话术 | 创作 + 1M 上下文 |
| 仓配调度 | 发货单、面单、物流节点跟踪 | 电脑操控 |
| 平台合规官 | 类目认证、标签、侵权、平台政策 | 网络安全意识 |

## 4. 「第一单」最短路径（12 步）

```
选品官定 1 个 SKU → 成本会计师出定价 → 视觉组出 5 张主图需求
→ Listing 专员成文 → 上传上架（电脑操控，留截图）
→ 投放手发 3 条种草帖 → 进入 1 条询盘
→ 多语客服应答 → 报价/改价（闸门⑤）
→ 付款（闸门⑥：老板确认）→ 仓配调度出面单 → 订单归档入账
```

## 5. 闸门与红线

- ⑤ 定价与折扣；⑥ 真实收款；④ 对外投放文案；合规红项（侵权/认证）一票否决
- **红线**：不刷单、不侵权、不用虚假时效承诺

## 6. 演示亮点（30 秒）

「三张商品图进去，可售卖的海外店铺链接出来；一条询盘进来，面单出来。」

## 7. 能力着力点

多模态（商品图）｜电脑操控（上架）｜创作（listing）｜办公（结算）｜安全（合规）

# 场景二 · 一人微 SaaS（Solo Dev）

## 1. 公司画像

做一个垂直小工具，订阅制收费。例：会议纪要自动转待办、电商客服自动回复、合同关键条款提醒。

**第一单定义**：定价页可支付 + 第一位付费用户（真实或模拟订阅成功）+ 欢迎邮件发出。

## 2. 全流程总表

| 阶段 | 目标 | 本场景专属交付物 |
|---|---|---|
| 0 立案 | 痛点真、范围小、能收费 | 痛点验证记录、竞品表、MVP 边界（砍掉 80%） |
| 1 开张 | 能收钱 | 域名、落地页、登录、支付、用户协议与隐私政策 |
| 2 产品 | 可用可试 | 仓库代码、测试报告、安全清单、Changelog |
| 3 营销 | 有试用 | 落地页文案、试用流、开发者社区帖、产品视频脚本 |
| 4 成交交付 | **第一单** | 订阅开通、支付凭证、发票、Onboarding 邮件序列 |
| 5 售后 | 不流失 | 文档、工单、反馈看板、答疑话术 |
| 6 财务 | 看得懂订阅生意 | MRR、流失率、获客成本、单位经济 |
| 7 复盘 | 决定下个版本 | 功能使用漏斗、NPS、版本 backlog |

## 3. 专属 Agent 编排

| Agent | 职责 | MiMo 能力 |
|---|---|---|
| 需求侦察 | 用户访谈纪要、痛点排序、砍需求 | 1M 上下文 + 推理 |
| 产品经理 | PRD、MVP 边界、验收标准 | 办公 |
| 架构师 | 技术选型、目录结构、接口设计 | Coding |
| 开发工程师 | 实现功能、写接口 | Coding |
| 测试员 | 用例、边界、回归 | Coding |
| 安全审计 | 依赖漏洞、鉴权、注入、密钥 | 网络安全 |
| 增长写手 | 落地页、社区帖、Changelog、视频脚本 | 创作 |
| Onboarding 专员 | 欢迎流、引导任务、激活提醒 | 办公 |
| 客户成功 | 工单、文档、续费预警 | 1M 上下文 |

## 4. 「第一单」最短路径

```
痛点验证 → 砍到 1 个核心功能 → 架构/开发/测试/安全（评审循环 ≤3 轮）
→ 落地页 + 定价页上线 → 社区发 2 条帖
→ 注册 → 试用 → 定价确认（闸门⑤）→ 支付（闸门⑥）
→ Onboarding 邮件发出 → 工单入口就绪
```

## 5. 闸门与红线

- ③ 功能范围（防膨胀）；⑤ 定价；⑥ 支付；④ 对外发帖/发版说明
- **红线**：不伪造用户评价；密钥不进对话；用户数据最小化

## 6. 演示亮点（30 秒）

「一个功能从需求到可支付上线；第一笔订阅进来，欢迎信自动发出。」

## 7. 能力着力点

Coding ｜ 网络安全 ｜ 创作 ｜ 办公（订阅/发票）｜ 推理（MVP 取舍）

# 场景三 · 一人内容工作室（Solo Media）

## 1. 公司画像

运营一个垂直领域账号矩阵（如：AI 工具 / 职场效率），变现 = 商单广告 + 付费专栏 + 咨询。

**第一单定义**：一份商单提案被接受并收到定金，或一份付费专栏售出。

## 2. 全流程总表

| 阶段 | 目标 | 本场景专属交付物 |
|---|---|---|
| 0 立案 | 有人设、有受众、有变现路径 | 赛道定位、人设卡、受众画像、变现结构 |
| 1 开张 | 有门面 | 账号矩阵、视觉体系、刊例（rate card）、接单邮箱 |
| 2 产品 | 内容能稳定产出 | 内容 SOP、选题库、模板（图文/视频脚本）、质检清单 |
| 3 获客 | 有流量有声量 | 发布排期、爆款复用表、互推/热点借势 |
| 4 成交交付 | **第一单** | 商单提案、合同/定金凭证、交付稿、结案报告 |
| 5 售后 | 粉丝与金主都满意 | 评论互动话术、品牌方沟通记录、修改流程 |
| 6 财务 | 知道哪种钱最好赚 | 收入结构表（商单/专栏/咨询）、单篇成本、账期 |
| 7 复盘 | 越做越准 | 爆款归因、受众增长、选题与报价迭代 |

## 3. 专属 Agent 编排

| Agent | 职责 | MiMo 能力 |
|---|---|---|
| 主编 | 选题定调、排期、终审 | 复杂推理 |
| 热点雷达 | 每日抓行业热点与竞品选题 | 电脑操控 |
| 写手 ×2 | 长文 / 短帖并行 | 创作 + 1M 上下文 |
| 视觉设计 | 封面、头图、信息图 | 设计 + 多模态 |
| 视频导演 | 分镜、口播、字幕 | 视频理解 |
| 合规检查 | 广告法、软文标注、禁词 | 网络安全意识 |
| 商务 | 刊例、提案、报价、合同要点 | 办公 |
| 发布运营 | 多平台排期、标签、投放 | 电脑操控 |
| 社群助理 | 评论、私信、高价值线索识别 | 创作 + 推理 |

## 4. 「第一单」最短路径

```
定位与人设卡 → 刊例价目表 → 产出 3 篇标杆内容（含 1 篇可带货）
→ 发布并记录数据 → 商务做 1 份提案（选一家目标品牌）
→ 提案确认（闸门⑤）→ 合同/定金（闸门⑥）
→ 创作交付（写手+设计+合规）→ 结案报告
```

## 5. 闸门与红线

- ④ 所有公开发布；⑤ 报价与商单承诺范围；⑥ 收定金；合规红项
- **红线**：不接与人设冲突的单；软文必须标注；不刷量

## 6. 演示亮点（30 秒）

「一个热点进来，5 分钟出选题包；一份商单提案进去，过审的交付稿和结案报告出来。」

## 7. 能力着力点

创作 ｜ 视频/多模态 ｜ 电脑操控（分发）｜ 办公（商单）｜ 长上下文（品牌规范一致性）

# 场景四 · 一人咨询工作室（Solo Studio B2B）

## 1. 公司画像

向中小企业卖「小而美」的专业服务：品牌 VI 小包、增长诊断、落地页/官网改造、AI 落地咨询。

**第一单定义**：一份提案获签 + 收到首付 + 项目启动会开完。

## 2. 全流程总表

| 阶段 | 目标 | 本场景专属交付物 |
|---|---|---|
| 0 立案 | 服务可卖、报价有据 | 服务定义卡（交付物/周期/价格带）、差异化、假想客户列表 |
| 1 开张 | 能见人 | 官网、提案模板、合同模板、项目协作空间、发票能力 |
| 2 产品 | 交付可复制 | 方法论手册、交付模板、质检清单、案例（可先做 1 个假想） |
| 3 获客 | 有线索 | 获客内容（诊断清单/行业观察）、转介绍机制、outreach 话术 |
| 4 成交交付 | **第一单** | 需求纪要、提案、合同、首付凭证、项目计划 |
| 5 售后/履约 | 客户觉得值 | 周报、评审记录、修改轮次、验收单 |
| 6 财务 | 别做白工 | 项目工时、成本、应收/账期、单项目毛利 |
| 7 复盘 | 接更好的单 | 客户满意、案例沉淀、涨价与标准化决策 |

## 3. 专属 Agent 编排

| Agent | 职责 | MiMo 能力 |
|---|---|---|
| 商机开发 | 目标客户清单、触达信、跟单 | 办公 + 创作 |
| 诊断顾问 | 需求访谈纪要、问题树、诊断报告 | 科研 + 推理 |
| 方案架构 | 提案结构、工作拆解、报价依据 | 复杂推理 |
| 设计/交付 | VI/页面/报告产出 | 设计 + 创作 |
| 项目经理 | 排期、周报、风险、升级 | 办公 |
| 合同法务 | 条款、范围边界、验收标准 | 办公 + 风控 |
| 质检 | 对照验收标准终检 | 复杂推理 |
| 财务 | 开票、催收、项目毛利 | 办公 |

## 4. 「第一单」最短路径

```
定 1 个标准化服务包 → 用假想客户做 1 份标杆案例
→ 筛 20 个目标客户 → 商机开发发触达信
→ 拿到 1 次需求沟通 → 诊断顾问出问题树
→ 方案架构出提案与报价（闸门⑤）→ 合同/首付（闸门⑥）
→ 项目计划 + 启动会纪要
```

## 5. 闸门与红线

- ⑤ 报价与范围边界；⑥ 合同与首付；⑦ 客户投诉/范围外要求
- **红线**：不承诺做不到的效果；范围外工作必须走变更单

## 6. 演示亮点（30 秒）

「一封客户邮件进去，问题树 + 提案 + 报价单出来；首付确认后，项目计划和启动会纪要自动就绪。」

## 7. 能力着力点

复杂推理 ｜ 办公（合同/项目）｜ 设计 ｜ 长上下文（客户资料）｜ 创作（提案）

# 场景五 · 一人知识付费（Solo Course）

## 1. 公司画像

一门录播课 + 一期轻量训练营，面向职场人售卖技能课（例：AI 提效、数据分析入门、独立开发入门）。

**第一单定义**：第一位付费学员入账 + 开课通知 + 进群/进平台。

## 2. 全流程总表

| 阶段 | 目标 | 本场景专属交付物 |
|---|---|---|
| 0 立案 | 有人买、你讲得了 | 选题验证（需求+竞品+学员画像）、课程承诺（学完能做到什么） |
| 1 开张 | 能卖课 | 课程页、支付、社群/平台、讲师权威材料（简介/案例/学员评价位） |
| 2 产品 | 课真的好 | 大纲、讲义、录播脚本、示例文件、作业与答案、试听课 |
| 3 获客 | 有人来听 | 试听课、干货帖、直播/分享会、分销话术、私域节奏 |
| 4 成交交付 | **第一单** | 售卖页成交、付款凭证、开课通知、学员档案 |
| 5 学员服务 | 学得完、有结果 | 答疑库、作业批改、督学、升单/续费沟通 |
| 6 财务 | 别被退款拖死 | 收入、退款率、获客成本、完课率 |
| 7 复盘 | 开第二期 | 完课与作业数据、口碑、大纲迭代、涨价决策 |

## 3. 专属 Agent 编排

| Agent | 职责 | MiMo 能力 |
|---|---|---|
| 选题官 | 需求验证、竞品课拆解、承诺设计 | 科研 + 推理 |
| 课程设计师 | 大纲、教学目标、案例编排 | 1M 上下文 |
| 讲师助理 | 讲义、PPT、口播稿、示例文件 | 创作 + 办公 |
| 出题助教 | 作业、答案、评分标准 | 复杂推理 |
| 视频制作 | 分镜、剪辑要点、字幕 | 视频理解 |
| 增长专员 | 试听课、干货帖、直播脚本、分销物料 | 创作 |
| 督学 | 提醒、答疑、作业催交 | 办公 + 创作 |
| 助教 | 基于讲义的学员答疑（同一 Context Hub） | 1M 上下文 |
| 数据分析 | 完课率、作业率、退款原因 | 复杂推理 |

## 4. 「第一单」最短路径

```
选题验证 → 大纲（含可承诺的学习结果）→ 做 1 节试听课 + 2 节正课样课
→ 课程页与支付上线 → 发干货帖 + 1 场直播
→ 试听 → 咨询（助教应答）→ 报价确认（闸门⑤）→ 付款（闸门⑥）
→ 开课通知 + 学员档案 + 入群
```

## 5. 闸门与红线

- ③ 课程承诺范围（防夸大）；⑤ 定价与退款规则；⑥ 收款；⑦ 投诉/退款
- **红线**：不伪造学员评价；不承诺「包就业包涨薪」；退款规则提前公示

## 6. 演示亮点（30 秒）

「一叠资料进去，大纲+讲义+作业出来；一位学员进来，开课通知和第一周督学计划自动就绪。」

## 7. 能力着力点

1M 长上下文（讲义一致性）｜ 创作 ｜ 视频 ｜ 办公（学员/财务）｜ 推理（出题）

# 五场景对照与选型建议

| 场景 | 最能秀的 MiMo 能力 | 第一单难度 | 评委记忆点 |
|---|---|---|---|
| 一 跨境小店 | 多模态 + 电脑操控 | 中 | 三张图 → 可售店铺 |
| 二 微 SaaS | Coding + 安全 | 中高 | 需求 → 可支付订阅 |
| 三 内容工作室 | 创作 + 分发 | 中低 | 热点 → 商单交付 |
| 四 咨询工作室 | 推理 + 办公 | 中 | 邮件 → 提案 → 首付 |
| 五 知识付费 | 长上下文 + 创作 | 中低 | 资料 → 课程 → 学员 |

**选型建议**

- 想秀「真开张、真交易」：选 **一** 或 **五**（闭环最直观）
- 想秀工程能力：选 **二**
- 想秀商业与提案能力：选 **四**
- 想秀传播与内容力：选 **三**

**通用做法（五者皆适用）**

1. 先保「第一单」闭环，再补财务与复盘
2. 所有对外动作过闸门④，所有钱过闸门⑥
3. 演示时故意暴露一次失败重跑，展示日志与 COO 升级
4. 提交物按总蓝图第 13 节清单准备

> 需要任一场景展开成「Agent 提示词 + 工具调用伪代码 + JSON Schema」，指名场景即可。
